Field

폼의 한 칸 — 라벨 · 컨트롤 · 도움말 · 오류가 한 묶음입니다. Text input 의 .field 를 그대로 쓰고, Select · textarea · Switch · Checkbox 묶음도 같은 뼈대에 들어갑니다. 여기서는 필수·선택 표시, 변경 점, 오류, 배치, 폼 전체의 간격과 검증 시점을 정합니다.

Anatomy

10자 이상, 결재 문서에 그대로 실립니다
사유를 10자 이상 적어 주세요
  1. Label — t1 500. <label for> 로 컨트롤과 연결
  2. Required mark — *, aria-hidden. 뜻은 컨트롤의 aria-required 가 전합니다
  3. Control — Text input · Select · textarea · Switch · Checkbox 묶음
  4. Help — 형식·범위 안내. 오류가 나도 남습니다
  5. Error — alert-circle 16 + 문구. aria-invalid="true" 가 켜져야만 선이 붉어지고, aria-describedby 로 연결

Fieldset

둘 이상 고를 수 있습니다

같은 질문에 답하는 컨트롤 여럿(Checkbox · Radio)은 <fieldset> + <legend> 로 묶습니다. legend 가 라벨 자리이고, 설명·오류는 묶음 아래 한 번만 — Checkbox · Radio group.

Validation timing

시점동작
입력 중아무것도 붉지 않습니다. :invalid 를 스타일에 쓰지 않는 이유
떠날 때(blur)그 필드만 검사해 aria-invalid + 오류 문구. 그 뒤로는 고치는 즉시 다시 검사(live)해 맞으면 바로 지웁니다
제출전부 검사 → 맨 위 요약(Callout danger, role="alert", 필드 링크) + 첫 오류 필드로 포커스·스크롤. 버튼은 비활성화하지 않습니다 — 눌러야 무엇이 틀렸는지 알 수 있습니다
서버 오류필드에 붙일 수 있으면 필드에, 아니면 요약에. 사용자가 적은 값은 지우지 않습니다

Guidelines

Do
원 단위, 부가세 포함
라벨은 명사 두세 단어, 형식은 help 에. 오류는 「사유를 10자 이상 적어 주세요」처럼 고치는 법까지.
Don't
필수 입력입니다
빈 폼을 열자마자 붉게 만들거나, 「필수 입력입니다」「잘못된 값」처럼 무엇을 해야 하는지 없는 문구.
Do한 폼에 한 가지 일. 연차 신청이면 종류·기간·사유·결재선까지 — 열 칸을 넘으면 섹션으로 나누거나 단계로 쪼갭니다.
Don't필수 별표와 「(선택)」을 한 폼에 섞지 않습니다. 둘 중 적은 쪽만 표시합니다.
