SERVICE Design System

이 디자인 시스템은 서비스의 화면·컴포넌트·상호작용을 하나의 정의로 묶어, 더 빠르고 일관된 사용자 경험을 만들기 위한 언어입니다.

Foundations {{ICON:arrow-right}}색·타이포·간격·라운드·아이콘 — 바탕이 되는 토큰과 원칙 Components {{ICON:arrow-right}}버튼·입력·목록·표 — 실제 CSS 로 렌더링된 조각과 규격, 복사할 수 있는 HTML

디자인 원칙

1. 명확하게한 화면에 강조는 하나. 브랜드색은 꼭 필요한 곳에만 쓴다.
2. 일관되게같은 뜻은 같은 모양. 상태 색·간격·라운드는 토큰에서만 온다.
3. 접근 가능하게글자 대비 AA 이상, 포커스 링, 키보드 조작을 기본으로 한다.

사용법

  1. tokens.css 를 프로젝트에 넣습니다. 값은 여기서만 바꾸고 이름은 유지합니다.
  2. 컴포넌트 CSS 는 semantic 토큰만 씁니다(--bg-brand-solid 처럼). --palette-* 는 semantic 이 없는 예외 상황에서만.
  3. 각 컴포넌트 페이지 맨 아래 HTML 을 복사해 시작합니다. 마크업과 클래스가 그대로 규격입니다.
  4. 아이콘은 Tabler Icons 만 씁니다 — Iconography.

Design Token

디자인 결정(색·크기·간격)에 이름을 붙인 것. 두 층으로 나뉩니다.

두 층

층역할예
Scale Token원시 값에 이름을 붙여 쓸 수 있는 값의 집합을 유한하게 유지--palette-brand-600 --dim-x4 --font-size-t3
Semantic TokenScale 을 조합해 의도를 표현. 디자인·개발이 실제로 쓰는 단위--bg-brand-solid --fg-neutral-subtle --spacing-global-gutter

명명 규칙

[속성]-[역할]-[강도] — 속성은 bg(배경) · fg(글자·아이콘) · stroke(선), 역할은 neutral brand critical positive warning info, 강도는 solid(칠) · weak(옅은 칠) · subtle/muted(글자 단계).

Color

색은 역할(semantic)로 씁니다. 팔레트를 직접 쓰는 것은 예외이며, 모든 글자색은 배경과 4.5:1 이상을 만족하도록 골랐습니다.

Typography

글꼴은 Pretendard, 크기는 t1(작음)부터 t10(큼)까지 열 단계. 굵기는 Regular 400 · Medium 500 · Bold 700 셋만 씁니다.

Iconography

아이콘은 Tabler Icons(MIT) outline 세트만 씁니다 — 손으로 그리지 않습니다. 24px 격자, 굵기 1.75, currentColor. 유니코드 글리프·이모지는 OS 마다 모양이 달라 UI 에 쓰지 않습니다.

크기

Outline / Filled

기본은 outline 입니다. 16px 이하로 작아지면 선이 뭉개지므로 filled(name-filled)를 씁니다 — 토스트·배지 옆 아이콘 칩(14px), 안내 말풍선(16px), 상태 점 대신 쓰는 아이콘.

Button

사용자가 행동을 실행하게 하는 가장 기본적인 요소. 화면의 주요 행동은 brand-solid 하나만 씁니다.

Anatomy

  1. Container — 크기·라운드·배경을 가진 상자(버튼 전체)
  2. Prefix icon (선택) — 라벨 앞 아이콘. xs 14 · sm 16 · md 18 · lg 20px
  3. Label — 동사로 끝나는 짧은 문구
  4. Suffix icon (선택) — 방향·펼침을 뜻할 때만

Guidelines

Do
